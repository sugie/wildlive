目的 (Objective)

WildLive の最小・再現可能なローカル開発環境を確立する。 具体的には Laravel 13 (PHP 8.5) + PostgreSQL を Docker Compose で構成し、 health endpoint、実 PostgreSQL に対する自動 PHPUnit スイート、 対応する GitHub Actions CI までを含める。

ゲーム機能 (hunter, zoo, expedition, discovery, multiplayer, authentication, deployment) は今回のスコープから明示的に除外されている。 今回の目的は純粋に土台の整備である。

アーキテクチャ / 設計判断 (Architecture / Design Decisions)

  • PostgreSQL 17 ではなく 16 を採用 — WildLive が production で利用予定の Sakura Cloud PostgreSQL appliance との整合性を優先した。
  • テストは SQLite ではなく実 PostgreSQL に対して実行 — WildLive で将来必要になる並行制御 (World First、所有権移転、expedition finalization) は PostgreSQL 固有の挙動に依存するため、テストエンジンも本番と同じである必要がある。
  • Nginx + PHP-FPM ではなく php artisan serve を採用 — dev stack を最小構成に保つ。production 向けの multi-stage image は将来 task に意図的に先送りする。
  • dev image は require-dev を含めて install — コンテナ内に PHPUnit / Pint 等が存在する必要があるため。production/dev image の分離は今回のスコープ外。
  • Laravel 標準の users/cache/jobs migration は保持 — framework の足場としてであり、WildLive のゲーム上の User ドメインではない。ゲーム側の User は将来のタスクで再設計され、このテーブルを置き換える可能性がある。
  • composer.lock を Composer container 内で pre-generate — PHP 8.5 に対して --ignore-platform-req で resolve。runtime image のビルド時は composer install のみで済み、決定論的なビルドを担保する。
  • Compose service は app と postgres の 2 つだけ — Redis、queue、WebSocket、mail、object storage は追加しない。追加する場合は docs/ARCHITECTURE.md に沿った明示的な task justification が必要。
  • PostgreSQL の port は 127.0.0.1 にのみバインド — 開発者のネットワーク上の他ホストからは到達できない。

既知の課題 / 未解決事項 (Problems / Known Limitations)

  • production 向けの multi-stage Dockerfile はまだ無い。現在の image は require-dev を含んでおり、クラウドデプロイ用途は想定していない。
  • wildlive_test データベースは初回に手動で作成する必要がある (docker compose exec postgres psql -U wildlive -d wildlive -c "CREATE DATABASE wildlive_test OWNER wildlive;")。テスト DB を自動生成する仕組みはまだ用意していない。
  • Migration は app コンテナの entrypoint では自動実行していない。デプロイ時にどう扱うかは将来の deploy task で決定する。
  • Load / security / resilience テストは未実施。本 task は開発土台であり、本番運用可否の証明ではない。
