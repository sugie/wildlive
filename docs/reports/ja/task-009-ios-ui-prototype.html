Task 009 — iOS コアループ UI プロトタイプ（Milestone 002、UI-first）

人による指示

リポジトリオーナー（人間）が、コアループ全体を UI プロトタイプとしてダミーデータで作ることを承認した。指示内容は、Milestone 001 のタイトル画面から続けて、UI のメインは引き続き SwiftUI、以下の一連の画面をシミュレーターで実際に操作して確認できるものを作ってほしい、というもの — トップ（ユーザーの最新ステータス）／自分の動物園／他人の動物園一覧／ギルド／ハンターを見つけて狩りを依頼／結果一覧／捕獲したアニマルの命名（Zoo に追加）or リリース／RevenueCat 型のゲーム内通貨 G 購入画面。すべてサーバー通信なしでシミュレーター内完結。AI が範囲（RevenueCat SDK は入れない、永続化なし、遠征タイマーはプロトタイプ用に短縮）と分岐ブランチ ai/013-ios-ui-prototype を提案し、人間が「GO」と応答した。

目的

Task 008 のタイトル画面を、WildLive のコアループを一巡できる SwiftUI プロトタイプに拡張する。ホーム／自分の Zoo／他人の Zoo／ギルド／契約／派遣／遠征結果／命名して展示 or リリース／G ストアまで、すべてインメモリのダミーデータのみで、iOS シミュレーター内で人間がクリックで確認できるようにする。バックエンドは一切関与させない。

何を出荷したか

アプリ

  • apps/ios/WildLive/ 配下に SwiftUI ソース 20 本を新規追加。project.pbxproj を手で更新し、20 本すべてを WildLive ターゲットに追加。
  • 状態管理 — AppStore を単一の @Observable にして、現在プレイヤー、他プレイヤー、ハンター、遠征、契約中ハンターなど、可変ゲーム状態をすべてここに集約。永続化はしない — 起動ごとに状態リセットは意図的。
  • ナビゲーション — NavigationStack を 1 本、AppStore.navigationPath にバインド。Route は宛先ごとに 1 ケースを持つ平坦な Hashable 列挙型。各 push は識別子だけを運び、モデル本体は運ばない。
  • ドメイン + ダミーデータ — Domain.swift が Species、Animal、Hunter、Region、Expedition、Player、GBundle を定義。SampleData.swift が実在種 18 種、4 階層のハンター 8 名、4 難度のリージョン 6 箇所、G バンドル 4 個、現在プレイヤー（初期アニマル 3 匹つき）、他プレイヤー 3 名を手で埋めている。
  • サービス層:
    • MockGameService — contract / dispatch / resolve / keepInZoo / release。resolve は idempotent（将来サーバー側で強制される遷移を模す）で、2 回目以降は既に確定した状態を返す。
    • MockGStoreService は GStoreServiceProtocol を実装し、RevenueCat 型 IAP を 形だけ模す。実際の RevenueCat SDK は入れていない。purchase は 0.8 秒待って（スピナー確認用）から MainActor で G 残高を加算するだけ。
  • 画面 — TitleView（START が AppStore.start() に配線された）、RootView、HomeView、MyZooView、OtherZoosView、VisitZooView、AnimalDetailView、GuildView、RegionPickerView、DispatchConfirmView、ExpeditionsView、ExpeditionResultView、CaptureNameView、GStoreView。全画面がセーフエリア尊重、ダークテーマ、縦向き固定。
  • プロトタイプ用に短縮した遠征タイマー — simulatedDurationSeconds は 8〜60 秒。docs/GAME_DESIGN.md の本来の 10 分〜24 時間ではなく、シミュレーター 1 セッション内でループを最後まで回せる長さに設定。サーバー側の本物のタイミングは別物。
  • apps/ios/README.md を更新: Milestone 002 のスコープ、依然として有効な非目標、CLI ビルド/テストコマンド、手動プレイスルー手順を追記。

方針的に明示しておく判断

  • @Observable のストア 1 本、DI フレームワークなし。全画面が @Environment(AppStore.self) 経由で AppStore を読む。UI-first フェーズでは意図的に抽象化を減らしている。将来 API が来たら、変わるのはサービス層（MockGameService、MockGStoreService）だけ。
  • MockGameService.resolve は idempotent。解決済み遠征を再度呼んでも再抽選せず、既に確定した状態を返す。将来サーバー側で強制される遷移を模しており、「遠征/発見の解決は複数回呼んでも安全でなければならない」という WildLive の非交渉ルールに一致。
  • プロトタイプ用の短縮遠征タイマー（8〜60 秒）。本来の 10 分〜24 時間（docs/GAME_DESIGN.md）ではシミュレーター 1 セッションでループを終えられない。短縮値はクライアント側の Region 構造体に置いてあり、「プロトタイプ値」であることが明白 — ゲーム設計の確定値ではない。
  • RevenueCat SDK なし。ストア画面は GStoreServiceProtocol を介するので、後日 View を触らずに実 RevenueCat 実装へ差し替え可能。バンドル一覧、スピナー、確認ダイアログ、エラーアラートの UI 要素はすべてモックで動作確認済。
  • ベーシック vs. 共有 ハンター。契約時に available=false になるのは非 basic ハンターだけ。ベーシックは常に契約可能のまま。docs/GAME_DESIGN.md の「ベーシックハンターは絶対に枯渇しない」という柱をモックでも守っている。

反復 2 — Apple SwiftUI デフォルトへ（初回レビュー後）

反復 1 を見た人間から、アプリ全体を Apple の素の SwiftUI 見た目 — 「SwiftUI デフォルトの青っぽいやつ」 — に書き直すよう指示があった。理由は Apple が実際に出している SwiftUI への敬意: 「AppleがSwiftUIを命懸けでこのUI作ってるわけじゃない　それに敬意を払ってAppleのSwiftUIでこのワイルドライブを再現してみたい」。反復 2 はコミット 4b7df48 として着地。

ビジュアル言語の切り替え

  • 全画面を List / Form / Section / LabeledContent / NavigationLink(value:) / Label(_, systemImage:) で組み直し。
  • 主要アクションは .buttonStyle(.borderedProminent) + .controlSize(.large)、副次ボタンは .bordered、破壊的操作は role: .destructive。
  • 購入確認は SwiftUI 標準の .alert(…, presenting:)、カウントダウンと遠征ステートバッジは SF Symbol とシステム意味色（.tint、.secondary、.red）に統一。
  • ダークグラデーション背景、独自の .card() モディファイア、.preferredColorScheme(.dark)、.toolbarBackground のオーバーライド、独自 hex 色をすべて削除。
  • Theme.swift は SpeciesRarity.systemColor と Region.Difficulty.systemColor だけ残した — ここでの色は情報（レア度／難度）を運んでおり装飾ではないため。
  • TitleView: 白背景 + システムタイポグラフィ + システムブルーの .borderedProminent Start ボタン。RootView はカラースキームを強制しない — アプリはシステム設定に追従。
