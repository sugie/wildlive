Task 010 — 初回プレイヤー登録エンドツーエンド（Milestone 002）

プロジェクト: WildLive  ·  日付: 2026-08-15  ·  AI エージェント: Claude Code (claude-opus-4-7[1m])  ·  状態: ローカルレビュー中 — PR 未作成

人による指示

リポジトリオーナー（人間）が「最初の実データ縦串」を要求した。iPhone Simulator から SwiftUI UI モックを操作し、Docker 上のローカル Laravel API を叩き、ローカル PostgreSQL 17 に Player 行を書き、JSON レスポンスを SwiftUI に戻し、DB に実際にレコードがあることを確認する — この最小 End-to-End をローカル環境だけで一周させる。範囲外として明示: ギルド、ランキング、マッチング、チャット、通貨、Push、AI 機能、pgvector、本番デプロイ、複雑な認証、管理画面、「後で必要になるから」の抽象化。AI が計画（ID 方式、Player フィールド、API パス、ブランチ）を提示し、人間が「OK GO」と応じ、AI が実装＋検証を行った。

目的

今後のすべてのゲーム機能が乗る「最小の実データ経路」を敷く。具体的に:

iPhone Simulator → SwiftUI → ローカル Laravel API（Docker）→ ローカル PostgreSQL → 登録 → API レスポンス → SwiftUI が識別子を受信 → 端末保存 → 次回起動以降は登録画面をスキップ。

設計判断

判断選択理由
Player・Zoo の主キー UUID（Laravel Str::orderedUuid()） Player.id は他プレイヤー訪問など URL に露出する。整数連番だと登録数が漏れ enumeration の的にもなる。時系列順 UUID なら B-tree 局所性を保ちつつその漏れを避けられる。
MVP 時点の Player フィールド id, display_name (2..32), timestamps docs/ER_MODEL.md が固定するミニマムに一致。認証方式・email・handle・公開識別子はすべて TBD で別タスク、追加マイグレーションで乗せる。
Player + Zoo の原子性 DB::transaction + UNIQUE(zoos.player_id) NOT NULL ER_MODEL C1 は原子生成を要求。tx は部分書き込みを、UNIQUE は将来の呼び出し元を守る。両方必要。
iOS ネットワーク層 URLSession.shared + async/await + Codable Apple デフォルト。サードパーティ HTTP ライブラリは不採用。
iOS 側セッション永続化 UserDefaults 現時点で保護すべき認証トークンがない。将来 Keychain / OAuth に切替える時は PlayerSession 一箇所を差し替えれば済む。
Info.plist 手書きに切替（GENERATE_INFOPLIST_FILE = YES を廃止） NSAppTransportSecurity の入れ子キーは INFOPLIST_KEY_* 経由で設定できない。手書きに切り替えるが、従来自動生成されていた launch/scene/orientation キーは同梱して挙動を保つ。
ATS の範囲 NSAllowsLocalNetworking = true シミュレータが http://localhost:8000 に届く必要がある。NSAllowsArbitraryLoads より狭く、localhost／*.local／unqualified hostname に限定される。
POST の冪等性 今回は Idempotency-Key は入れない 登録は自然に冪等でない（毎回別 Player を作るのが正しい）。冪等キーは Expedition や金銭移動が入ってから重要になり、そのタスクで扱う。
