Task 006 — 開発環境と CI を PostgreSQL 15 に統一

Project: WildLive  ·  日付: 2026-08-14  ·  AI Agent: Claude Code (claude-opus-4-7[1m])  ·  Status: main に merge 済み

人間による介入 (Human intervention)

本番で使用する Sakura Cloud PostgreSQL Appliance のメジャーバージョンが 15 であることを人間 (repository owner) が確定し、ローカル開発環境と CI も PostgreSQL 15 に統一する、という判断を行った。 AI (Claude Code) は repository を audit し、最小限の編集を行い、実サーバのバージョンを検証し、ADR-0004 を執筆して、このレコードを ship した。

過去の記述の訂正

Task 001 の bilingual report は「postgres:16-alpine は Sakura Cloud PostgreSQL appliance との整合のために採用した」と記していた。人間が今回、appliance のメジャーバージョンは実際には 15 であることを確認した。Task 001 report は 遡って書き換えていない — 当時の理解を正しく記録した audit record として保持する。ADR-0004 が今後の選択を正式に訂正し、過去 report への provenance link を張っている。

目的 (Objective)

開発 / CI / 本番の PostgreSQL メジャーバージョンを揃える。そのために必要な最小限だけ行う: pin されている image tag 2 か所を変更、バージョンに言及している docs の rationale を訂正、決定を ADR として記録、そして「image tag ではなく実サーバに対して」 15.x であることを検証する。

PostgreSQL 15 互換性 audit

本 task の一環として実施。互換性修正は不要だった。

  • pgvector 無し。 repository 全体で pgvector, CREATE EXTENSION, USING ivfflat, USING hnsw, vector( のいずれも 0 hit。postgres:15-alpine base image は pgvector を同梱しておらず、WildLive の現状では不要。
  • raw SQL 無し。 現在 ship されている migration 3 件 (0001_01_01_000000_create_users_table, 0001_01_01_000001_create_cache_table, 0001_01_01_000002_create_jobs_table) は Laravel Blueprint API のみを使用しており、PostgreSQL 15 以前でもサポートされる portable な SQL に compile される。
  • アプリケーションコード。 PostgreSQL 固有の呼び出しは health check の DB::selectOne('select version() as version') と tests/Feature/HealthTest.php の identity assertion のみ。いずれも 15.x で同一に動作する。
  • 設定。 .env.example は DB_CONNECTION=pgsql と service hostname postgres を使用。アプリ層でメジャーバージョンを pin していない。
  • PostgreSQL 16 以降専用機能 (MERGE … RETURNING、IS JSON、拡張された logical-replication surface、ICU default collations 等) はいずれも未使用。

Volume 移行に関する注意

ローカルで postgres:16-alpine により初期化された wildlive_postgres-data volume を持つ開発者は、新スタック起動前に docker compose down -v を実行する必要がある。PostgreSQL 15 は上位メジャーで初期化された data directory を開くことを拒否する。影響を受けるのはローカルの破棄可能データのみ — WildLive は developer マシンに本番データを一切保存しない。
