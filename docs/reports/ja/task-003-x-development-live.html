人間による介入 (Human intervention)

WildLive の開発過程そのものを X に公開する、という判断は人間 (repository owner) が行った。 Claude Code は、その方針に沿って 自動化を設計・実装し、publisher / workflow / tests / 最初の manifest を 書いた。AI は以下を 行っていない:

  • X Developer app の作成、
  • X API credentials の生成 / 設定、
  • kill switch X_AUTOPOST_ENABLED の有効化、
  • X アカウントの profile / bio / automated-account label の変更。

これらの操作は docs/social/x/README.md にまとめてあり、人間の作業として残る。

目的 (Objective)

検証可能な WildLive の開発マイルストーンを X に自動投稿する、 fail-closed で audit 可能なパイプラインを整備する。ただし runtime での hallucination を許さず、workflow 側が投稿文を新規生成できないようにする。

これは ゲーム内 X 連携ではない。 自律開発実験そのものを外に見せるための broadcast チャネルである。

アーキテクチャ: AIが書き、Gitが記録し、PRがレビューし、workflowが配送する

X 投稿は docs/social/x/ にコミットされた JSON manifest から生成する。AI が PR 作成時に文面を書き、reviewer が PR 上で確認し、 GitHub Actions は manifest に PR URL と #shipaton を連結して 送信するだけ。runtime で LLM を呼ばない。

Trigger と safety guards

Guard挙動
Event フィルタworkflow_run.conclusion == success ∧ workflow_run.event == push ∧ workflow_run.head_branch == main。PR open や PR CI が緑になっただけでは絶対に発火しない。
関連する merged PR が見つからないclean skip (no-op)。direct push で投稿することは決して無い。
PR diff に manifest が 0 件意図的 no-op (typo fix、one-line 変更)。
PR diff に manifest が 2 件以上fail closed — どちらを投稿するか AI が推測することは無い。
Kill switch X_AUTOPOST_ENABLED != "true"clean skip、disabled — no post と記録。live mode でも適用。
X credentials 4 つのうち 1 つでも欠落clean skip — 部分署名の request は絶対に送らない。
Idempotency: audit issue に同じ merge SHA marker が既存clean skip (already posted — skip)。workflow を re-run しても重複投稿されない。
Concurrency group を merge SHA で keying同じ SHA に対する workflow_run と workflow_dispatch の同時実行は serialise される。
Length 上限network に到達する前に、conservative な twitter-text 近似 (CJK 文字 = weight 2、URL = 23、cap 280) で over-length manifest を rejects。
Retry policymax 3 attempts。429 / 5xx / transport error のみ retry。それ以外の 4xx は即失敗。
Workflow permissionscontents: read, pull-requests: read, issues: write のみ。contents: write や actions: write は与えない。
Secret 取扱いcredentials は env のみから読む。OAuthCredentials.__repr__ は redacted。secret が stdout / stderr / job summary に出ることは無い。

既知の課題 / 未解決事項 (Problems / Known Limitations)

  • Live posting の end-to-end 検証は、本 PR 内では行えない。人間が X credentials を設定し kill switch を有効化して初めて可能になる。real X API を CI から呼ぶことは意図的に避けている (credentials 消費、paid tier 課金リスク)。
  • POST /2/tweets の made_with_ai disclosure フィールドは 本実装では送信していない。現在の production endpoint でこのフィールドが受理されるか、本 repository 内から確認できなかったため。人間側で最新公式仕様を確認して supported と判明したら、小さな follow-up PR で追加できる。AI 生成の transparency は現状、#shipaton hashtag、X アカウント側 (人間が設定) の automated-account 表示、そして投稿が指す WildLive report によって示す。
  • publisher 自身は audit issue にコメントを書かない (workflow 側の役割)。POST /2/tweets 成功後、audit comment を書く前に crash した場合、その merge に対する ledger が inconsistent になる。concurrency group と workflow の失敗時挙動 (自動 job re-run を行わない) により影響は限定的で、万が一発生した場合は人間が marker を手動で追記できる。
  • scripts/social/post_x.py を workflow 外部から直接実行した場合、audit 重複抑制は働かない。workflow を通した実行を想定している。
