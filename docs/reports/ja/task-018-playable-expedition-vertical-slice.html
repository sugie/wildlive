目的

WildLiveを「本物の登録機能＋モックのゲーム」から、実際に遊べる最初のゲームループへ進める。 ローカル環境で iPhoneシミュレータ → SwiftUI → Laravel API → PostgreSQL 17 → 永続化されたゲーム状態 → 再び画面へ、 という一連の流れを成立させる。人間が実際に、登録し、アフリカのマップを選び、ハンターと契約し、探検を送り出し、 結果を確定させ、動物をKEEP（命名）またはRELEASEし、My Zooで確認できること。 そのすべての事実がサーバー側に保存されていること。

意図的に対象外としたもの: 本番デプロイ、さくらのクラウド、RevenueCat、認証、マルチプレイ／ギルドの同時実行制御、 PvP、トレード、チャット、経済バランスの完成、アフリカ以外のリージョン、高度な動物園シミュレーション。

アーキテクチャ／設計上の判断

  • マスターデータの経路を一本に — ワークブックとJSONは同じPythonリテラルから生成されるため、共通の源泉が変わらない限り両者が食い違うことはない。RUNTIME_MASTER_DATA.mdに記載。
  • Game MasterのIDをそのまま主キーに（map_kenyan_savanna_001）— 表計算のセルからAPIのペイロードまで、対応表なしに目視で追跡できる。
  • ルールは「忘れうるチェック」ではなく構造で担保する。 キタシロサイはmap_animalsに行を持たないため、どの経路からも出現し得ない。player_huntersテーブルが存在しないため、ハンターを所有することはできない。rare_find_bonusはEncounterTable以外のどこからも参照されないため、捕獲成功率に混入し得ない。
  • 注入可能な乱数 — すべてのロールが単一のインターフェースを通るため、テストがサイコロの目で落ちることはない。
  • べき等な状態遷移 — 結果確定はresolved_at、KEEP/RELEASEはdecided_atで守り、いずれもSELECT … FOR UPDATE下で実行。最後の砦としてUNIQUE(zoo_animals.expedition_id)を置いた。
  • 開発専用の時間短縮は本番と絶対に混同できない形に — 許可された環境・設定フラグ・リクエストごとの明示的な指定の3つすべてを要求する。生成された探検はPostgreSQLとすべてのAPIレスポンスに恒久的にフラグが立ち、アプリではオレンジ色の帯が表示され、本来の所要時間はplanned_duration_minutesに保持される。正典のexpedition_minutesは一切変更していない。
  • プロトタイプ型は並存させず削除 — クライアント側のMockGameService・Hunter・Region・Expeditionは、サーバー実装が入った時点で削除した。「ハンターとは何か」の答えは常に一つである。
  • ユースケースは必要な場所にだけ — 書き込み系のフローにはApplicationユースケースを置き、参照のみの画面はDomainプロトコルへ直接依存させた。本プロジェクト既存の「転送するだけのユースケースを作らない」という方針に従っている。

問題点／既知の制約

発見して修正したバグ。うち4件は本タスク以前から存在していた。

  1. PHPUnitのテストスイートが開発用データベースに対して実行され、それを消していた。 docker-compose.ymlがappコンテナにDB_DATABASE=wildliveを渡し、PHPのCLIがコンテナの環境変数を$_SERVERへ複写し、Laravelのenv()は$_SERVERを$_ENVやputenv()より先に読む。PHPUnitの<env>が書き込むのは後者だけである。失って困るものが無いうちは無害だったが、本タスクではセッション途中で投入済みのGame Masterデータを消し、動作中のアプリを壊した。<server>要素の追加で修正。CIは常に正しく、だからこそ見過ごされていた。
  2. 「実API」UIテストが黙ってスキップされ続けていた。 テストランナープロセス（アプリ側ではない）から到達性をpingする自己ゲートを持ち、それが成功することはなかったため、本プロジェクト唯一のE2Eテストは何も検証しなくなっていた。明示的なWILDLIVE_E2Eオプトインに置き換え、指定時はスキップではなく失敗するようにした。
  3. JSONDecoder.iso8601がLaravelのマイクロ秒付きタイムスタンプを拒否していたため、全レスポンスの全日付がデコードに失敗していた。クライアントは両方の表記を受け付けるようにした。
  4. ExpeditionRejected::$codeがException::$codeをreadonlyとして再宣言していた — 全ての拒否経路でPHPの致命的エラーになっていた。
  5. AIが持ち込んだ退行: 上記1の最初の修正がDB_*をすべて強制上書きし、CIが正しく与えているホストとパスワードを潰した。PR上のCIが検出し、上書き対象をデータベース名のみに絞り込んだ。

運用上の注意点。

  • E2Eテストは-parallel-testing-enabled NOで実行すること。php artisan serveはシングルスレッドであり、3つのシミュレータクローンが同時に叩くとリクエストがタイムアウトするまで待ち行列になる。
  • xcodebuildはTEST_RUNNER_接頭辞の付いた環境変数しかテストプロセスへ渡さないため、ゲートはTEST_RUNNER_WILDLIVE_E2E=1となる。
  • トランザクションのガードは構造上正しいが、実際の競合下での検証は行っていない（負荷テストなし）。

Game Master v0.3が定めていない値 — 本スライスのために選んだ値であり、ExpeditionBalanceとRUNTIME_MASTER_DATA.mdに「決定ではなく未解決の課題」として明記している: 2つの−8難易度ペナルティ、[5, 95]の捕獲確率クランプ、初期1000 G、そしてZoo ValueをRarity.base_multiplierを掛けずにbase_zoo_valueの総和として読むこと。
