人間による介入 (Human intervention)

WildLive のゲームシステムの根幹は、人間 (repository owner) がインタラクティブな設計セッションの中で決定した。 今回のタスクにおける AI の役割は、その決定内容を整理し、 repository 全体に一貫した形で文書化し、既存の working notes との矛盾を解消することである。 AI がゲームのルールを自分で作ったわけではない。セッション で決まっていない事項は、推測で埋めずに「未決定」として 明示的に記録している。

  • 人間が決定した内容: ADR-0002 の 19 項目に記載した全て — コアコンセプト、実在動物のみ、Species と Animal の分離、実在の生物学的特徴による個体レア度モデル、Hunter の用語統一と能力/コストのカーブ、Guild ベースの Hunter プールと共有希少性、capture / no capture の失敗モデル、経営 sim にしない Zoo、diminishing returns 付きの Zoo Value、Visitors 経済、通貨名 (G)、盗み禁止の multiplayer、実在動物を用いた Seasonal Event、power inflation を避ける方針、Animal の historical identity、monetization は将来方針のみ。
  • AI が実施した作業: source-of-truth ドキュメントの読了、セッション内容から ADR-0002 の起草、docs/GAME_DESIGN.md と docs/DOMAIN_MODEL.md の整合的な書き換え、docs/DECISIONS_PENDING.md からの解決済み事項の移動、docs/ROADMAP.md の更新、README.md と docs/VISION.md からの「Explorer」「unknown creatures」表現の除去、そして本 bilingual report の作成。
  • AI が勝手に決めなかったこと: 具体的な species 一覧、region 名、数式、価格、アルゴリズム、DB schema。すべての未決定項目は docs/DECISIONS_PENDING.md に明示的に残してある。

アーキテクチャ / 設計判断 (Architecture / Design Decisions)

19 項目のフルリストは docs/adr/0002-game-system-foundation.md にある。将来の AI agent とレビュワーが必ず把握すべきハイライト:

  • 実在動物のみ。 架空・fantasy creature は使わない。mystery は実在の rare trait と探索報告の表現で伝える。
  • Species ≠ Animal。 Species は global master data。Animal は捕獲された個体であり、独自の traits, sex, weight, rarity, 履歴を持つ。同じ Species でも別 Animal は別 entity。
  • Species 目標数: 120。 ただし hard な technical constant ではなく、design goal。
  • Hunter 用語で統一。 「Explorer」は全ドキュメントで非推奨。
  • Guild ベースの Hunter プール。 上位 Hunter は全プレイヤー共有の有限資源。一方 basic-tier Hunter は必ず契約可能で、初心者が常にゲームを開始できることを保証する。player-to-player の Hunter 貸出は MVP スコープ外。
  • capture / no-capture の結果モデル。 低能力 Hunter を高難易度 Region に送ることは禁止しないが、no capture で帰ってくる確率が高くなる。
  • Zoo は経営 sim ではない。 MVP では food / land / staffing / cleaning / illness / budget を導入しない。
  • Zoo Value ランキング、ただし diminishing returns を織り込む: 同じ Animal を大量に集めるだけで支配できてはいけない。
  • 盗みは禁止。 multiplayer の competition は collection / Zoo Value / ranking / Hunter 共有希少性のみ — attack / destruction / theft は決して含まない。
  • Power inflation は取らない。 追加コンテンツは「より珍しい」動物であって、「より強い」動物ではない。
  • Historical / event identity は保持。 古い Animal が新しい Animal より弱くなって価値を失う設計は取らない。
  • Monetisation は将来方針のみ。 本 ADR では価格・特典・RevenueCat 統合・payment code は一切決めない・実装しない。
