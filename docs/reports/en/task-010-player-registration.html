Task 010 — First-time Player registration end-to-end (Milestone 002)

Project: WildLive  ·  Date: 2026-08-15  ·  AI Agent: Claude Code (claude-opus-4-7[1m])  ·  Status: In local review — PR not yet opened

Human intervention

The human (repository owner) asked for the first real vertical slice: from the iOS Simulator, drive the SwiftUI UI mock, call the local Laravel API in Docker, write a Player row to the local PostgreSQL 17, receive the JSON response back in SwiftUI, and confirm the row exists in the database. Explicitly out of scope: Guild, ranking, matching, chat, currency, push, AI features, pgvector, production deployment, complex auth, admin console, or any "we'll need this later" abstractions. The AI produced a plan (ID scheme choice, Player fields, API path, branch), the human replied OK GO, and the AI implemented and verified the slice.

Objective

Establish the smallest possible end-to-end path so every later game feature can rest on it. Specifically:

iPhone Simulator → SwiftUI → local Laravel API (Docker) → local PostgreSQL → registration → API response → SwiftUI receives the registered identifier → the app persists the identifier so subsequent launches skip registration.

Design decisions

DecisionChoiceWhy
Player & Zoo primary key UUID (Laravel Str::orderedUuid()) Player IDs will appear in URLs (visit another player's Zoo). Sequential integers leak "how many players joined" and enable enumeration. Time-ordered UUIDs give good B-tree locality without that leak.
Player fields at MVP id, display_name (2..32), timestamps Matches the minimum required by docs/ER_MODEL.md. Authentication method, email, handle, and public identity are still TBD — those are separate future tasks and additive migrations.
Player + Zoo atomicity DB::transaction + UNIQUE(zoos.player_id) NOT NULL ER_MODEL C1 requires atomic creation. Both the tx and the unique constraint are needed — the tx protects against partial writes, the constraint protects against future callers.
iOS network stack URLSession.shared + async/await + Codable Apple defaults. No third-party HTTP library.
iOS persistence of the session UserDefaults There is no auth token to protect yet. PlayerSession is the single class to swap when Keychain / OAuth arrives.
Info.plist Hand-authored file, replaces GENERATE_INFOPLIST_FILE = YES Nested keys under NSAppTransportSecurity can't be set through INFOPLIST_KEY_* build settings. The hand-authored plist keeps every previously auto-generated key so behaviour is unchanged, plus adds ATS and the API base URL.
ATS scope NSAllowsLocalNetworking = true Simulator needs to reach http://localhost:8000. This key is strictly narrower than NSAllowsArbitraryLoads — only localhost, *.local, and unqualified hostnames are permitted.
Idempotency on POST Not adding an Idempotency-Key header for now The scope is registration only, which is not naturally idempotent (each call is meant to create a new player). Idempotency keys become important once we start creating Expeditions and financial motion, and belong to that task.

Deliberate non-goals (still in force)

  • No authentication of any kind. No password, no email verification, no OAuth, no JWT, no session cookie. display_name is not unique — enforcing uniqueness before auth would just push the collision problem into a place with no recovery UI.
  • No other domain tables (Hunter, Species, Region, Expedition, Animal, HunterContract, SeasonalEvent) and no currency. The rest of the app still runs against the same in-memory dummy data as Task 009.
  • No pgvector usage.
  • No production deployment, no touch of the production PostgreSQL, no CI change for iOS. This task ran entirely on the local Mac.
  • No Idempotency-Key plumbing — see the design table.
  • No RevenueCat SDK, no push notifications, no analytics.

Problems / Known Limitations

  • The test_realAPI_endToEndRegistration test writes real rows to the local wildlive database and does not clean up after itself. The developer is expected to TRUNCATE zoos, players CASCADE; between runs. The pre-existing PHPUnit suite uses RefreshDatabase against wildlive_test and is unaffected.
  • Error messages surfaced from a failed POST currently include the raw response body prefix (up to 200 chars). Fine for now; when we add real API error shapes we should decode errors.display_name[0] and surface that inline on the form.
  • The app currently ignores server_created_at once the session exists — the seeded Player also carries a placeholder gBalance = 1_200 and no animals until server-side domain endpoints arrive. This is deliberate; Task 010's scope was registration only.
