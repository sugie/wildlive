Task 003 — X Development Live

Project: WildLive  ·  Date: 2026-08-14  ·  AI Agent: Claude Code (claude-opus-4-7[1m])  ·  Status: Merged into main  ·  Live posting: Disabled until human activation

Human intervention

The human (repository owner) decided to make WildLive development itself publicly visible on X and defined the goal of an AI-authored bilingual live-development feed. The AI (Claude Code) designed the automation under the constraints given by the human, implemented the publisher, wrote the workflow and tests, and drafted the first manifest. The AI did not:

  • create an X Developer app,
  • generate or install X API credentials,
  • flip the kill switch X_AUTOPOST_ENABLED,
  • modify the X account profile, bio, or automated-account label.

Those steps are described in docs/social/x/README.md and remain a human responsibility.

Objective

Establish a fail-closed, auditable pipeline that publishes verified WildLive development milestones to X, without allowing runtime hallucination and without giving the workflow the ability to compose new text at post time.

This is not an in-game X integration. It is a broadcast channel for the autonomous-development experiment itself.

Architecture: AI writes, Git records, PR reviews, workflow publishes

Every X post is derived from a JSON manifest committed to docs/social/x/. The AI writes the wording at PR-authoring time; reviewers read it in the PR; the GitHub Actions workflow only concatenates the manifest with a PR URL and the #shipaton hashtag and sends it. The runtime never calls an LLM.

Trigger and safety guards

GuardBehaviour
Event filterworkflow_run.conclusion == success ∧ workflow_run.event == push ∧ workflow_run.head_branch == main. PR opens and PR CI going green never trigger.
No associated merged PRSkip cleanly (no-op) — never post from a direct push.
Zero manifests in PR diffIntentional no-op (typo fixes, one-line changes).
Two or more manifests in PR diffFail closed — never guess which to post.
Kill switch X_AUTOPOST_ENABLED != "true"Skip cleanly, log disabled — no post. Applies even in live mode.
Missing any of the four X credentialsSkip cleanly — never send a partially-signed request.
Idempotency: merge SHA already in audit issueSkip cleanly (already posted — skip). Workflow re-runs cannot double-post.
Concurrency group keyed on merge SHASimultaneous workflow_run and workflow_dispatch for the same SHA serialise.
Length capRejects over-length manifests locally before touching the network. Uses a conservative twitter-text approximation (CJK char = weight 2, URL = 23, cap 280).
Retry policyBounded max 3 attempts. Retries on 429/5xx/transport errors only. 4xx (other than 429) fails fast.
Workflow permissionscontents: read, pull-requests: read, issues: write only. No contents: write, no actions: write.
Secret handlingCredentials read from env only. OAuthCredentials.__repr__ is redacted. No secret is ever written to stdout, stderr, or the job summary.

Problems / Known Limitations

  • Live posting cannot be verified end-to-end from within this PR without human-supplied X credentials and a flipped kill switch. The workflow's real X call remains unexercised in CI by design — real API calls from CI would burn credentials and could hit paid tiers.
  • The made_with_ai disclosure flag on POST /2/tweets is not sent by this implementation. The presence and accepted values of that field on the current production endpoint could not be verified from within this repository. If human verification confirms it is supported, a small follow-up PR can add it. AI-generation transparency is currently signalled through the #shipaton hashtag, the automated-account framing on the X account itself (human-configured), and the WildLive reports the posts link to.
  • The publisher does not itself write the audit-issue comment; the workflow does, so that the publisher stays free of GitHub API dependencies. A crash after POST /2/tweets succeeds but before the audit comment is written would leave the ledger inconsistent for that merge. The concurrency group and the workflow's failure-mode behaviour (no automatic retry of the whole job) keep this bounded; a human can, if it ever occurs, manually append the marker.
  • The publisher accepts a merge-commit SHA implicitly via the workflow. If a human runs scripts/social/post_x.py outside the workflow, no audit deduplication happens — the workflow is the intended entry point.

Human setup required to activate

Note the design constraint: the kill switch X_AUTOPOST_ENABLED gates every live call, including manual workflow_dispatch runs with dry_run = false. Setting the switch to true is therefore not a "verified-and-done" flag; it is the authorisation that unlocks any live posting, including the first controlled test. It can be toggled off again in seconds if anything looks wrong.

  1. Read X's current Automation Rules and configure the posting account (label, linked human account if required). The AI does not touch the X profile.
  2. Create the X Developer App and generate the four OAuth 1.0a credentials. Add them to GitHub Actions Secrets: X_API_KEY, X_API_KEY_SECRET, X_ACCESS_TOKEN, X_ACCESS_TOKEN_SECRET.
  3. Create the audit issue once with gh issue create --title "[automation] WildLive X Development Live Audit" --body "Automated audit log."
  4. Confirm the repository Variable X_AUTOPOST_ENABLED is unset (or false) — this is the default that shipped with the implementation PR.
  5. Run the workflow manually with the switch still off: Actions → X Development Live → Run workflow, keeping dry_run = true. Confirm the rendered preview. Nothing is posted to X in this state, by design.
  6. If the preview is correct, set X_AUTOPOST_ENABLED = true. This authorises live posting; it does not by itself post anything (no automatic event has fired).
  7. Immediately run the workflow manually one more time with pr_number = <N> (a known merged milestone PR) and dry_run = false. This sends exactly one live post. Verify the post appears on X and that the new audit marker was appended.
  8. If anything looks wrong at any point, set X_AUTOPOST_ENABLED back to false (or delete the variable) immediately. Subsequent runs short-circuit at the kill switch; credentials do not need to be touched.
  9. If the controlled live test looked correct, leave X_AUTOPOST_ENABLED = true. From that moment, future task/milestone merges publish automatically.
