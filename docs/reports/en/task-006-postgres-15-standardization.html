Human intervention

The human (repository owner) confirmed that the Sakura Cloud PostgreSQL Appliance used in production is PostgreSQL 15, and decided to standardise the local development environment and CI on PostgreSQL 15 to match. The AI (Claude Code) audited the repository, made the minimum edits, verified the running server version, wrote ADR-0004, and shipped this record.

Task 001's bilingual report claimed that postgres:16-alpine was "chosen for alignment with the Sakura Cloud PostgreSQL appliance". Do the minimum needed to achieve that: change the two pinned image tags, correct the rationale in the docs that mention the version, capture the decision as an ADR, and actually verify the live server reports 15.x — not just the image tag.

PostgreSQL 15 compatibility audit

Performed as part of this task; no compatibility fixes were required.

  • No pgvector. Grep for pgvector, CREATE EXTENSION, USING ivfflat, USING hnsw, vector( returned zero hits across the repository. The base postgres:15-alpine image does not bundle pgvector, and no part of WildLive currently requires it.
  • No raw SQL. All three shipped migrations (0001_01_01_000000_create_users_table, 0001_01_01_000001_create_cache_table, 0001_01_01_000002_create_jobs_table) use Laravel Blueprint methods that compile to portable PostgreSQL syntax supported by PostgreSQL 15 and earlier.
  • Application code. The only PostgreSQL-specific call is DB::selectOne('select version() as version') in the health check and one identity assertion in tests/Feature/HealthTest.php. Both work identically on 15.x.
  • Configuration. .env.example uses DB_CONNECTION=pgsql and the service hostname postgres; nothing pins a major version at the application layer.
  • No PostgreSQL-16-or-newer-only feature (e.g. MERGE … RETURNING, IS JSON, expanded logical-replication surface, ICU default collations) is used.

Volume migration

Any developer with an existing local wildlive_postgres-data volume built by postgres:16-alpine must run docker compose down -v before the new stack will start. PostgreSQL 15 refuses to open a data directory that was initialised by a newer major version. This affects only local disposable data — WildLive stores no production data on developer machines.
