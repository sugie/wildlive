pgvector version reconciliation

Production runs pgvector 0.8.5; the dev image pgvector/pgvector:pg17 ships pgvector 0.8.6. Both are on the 0.8.x line and are API-compatible for the operations WildLive is currently designing around. ADR-0005 deliberately does not pin the pgvector patch version — no application code depends on a specific pgvector feature today. If a future task adds vector-index code that relies on a particular pgvector patch, that task should pin the image to a specific tag and record the pin in its own ADR.

Compatibility audit

Performed as part of this task; no code changes required.

  • No raw SQL migrations. All three shipped migrations use Laravel Blueprint methods that compile to portable SQL supported on both PostgreSQL 15 and 17.
  • The one PostgreSQL identity assertion in tests/Feature/HealthTest.php (stringContainsStringIgnoringCase('postgresql', $version->version)) works identically against 17.x.
  • No application code used any PostgreSQL-15-only construct that would need a PostgreSQL-17 equivalent.
  • The Task 006 report, X manifest, and AI session archive contain textual references to PostgreSQL 15 as historical fact — they are audit records of that decision, not active spec.

Tests

  • No new automated tests. The change is a version bump + doc update; existing suites already exercise the paths that matter (PostgreSQL connectivity via HealthTest, migration execution, publisher rendering, session-archive validation).
  • All three test suites — PHPUnit 5/9, publisher 55/55, validator 35/35 — pass unchanged on the new PostgreSQL 17 + pgvector stack.
  • No test was weakened or skipped.

Volume migration

Any developer with an existing local wildlive_postgres-data volume built by postgres:15-alpine (i.e. anyone who ran the Task 006 stack) must run docker compose down -v before the new stack will start. PostgreSQL 17 refuses to open a data directory belonging to a different major version. This affects only local disposable data — WildLive stores no production data on developer machines. In this session the AI reported the situation before executing the wipe, per the human's explicit instruction.
