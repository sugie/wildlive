Objective

Establish a minimal, reproducible local development environment for WildLive: Laravel 13 on PHP 8.5 with PostgreSQL, orchestrated by Docker Compose, plus a health endpoint, an automated PHPUnit suite exercised against real PostgreSQL, and a matching GitHub Actions CI workflow.

The task deliberately excluded all game features (hunters, zoos, expeditions, discoveries, multiplayer, authentication, deployment). Its scope was pure plumbing.

Architecture / Design Decisions

  • PostgreSQL 16, not 17 — chosen for alignment with the Sakura Cloud PostgreSQL appliance that WildLive intends to deploy against in production.
  • Tests run against real PostgreSQL, not SQLite — WildLive's future concurrency semantics (World First, ownership transfer, expedition finalization) depend on PostgreSQL-specific behaviour, so the test engine must match.
  • php artisan serve instead of Nginx + PHP-FPM — the minimum viable dev stack. A production multi-stage image is intentionally deferred to a future task.
  • Dev image installs require-dev — PHPUnit, Pint, and friends must exist inside the container. Production/dev image separation is out of scope for this task.
  • Laravel's default users/cache/jobs migrations are kept as framework scaffolding, not as game domain. The WildLive User aggregate will be redesigned in a later task and may or may not replace this table.
  • composer.lock pre-generated via a Composer container using --ignore-platform-req for PHP 8.5, so the runtime image build only needs composer install. This keeps the image build deterministic.
  • Only app and postgres services — no Redis, queues, WebSockets, mail, or object storage. Any addition requires an explicit task justification per docs/ARCHITECTURE.md.
  • PostgreSQL port bound to 127.0.0.1 only so it cannot be reached from other hosts on the developer's network.

Problems / Known Limitations

  • No production-grade multi-stage Dockerfile yet. The current image installs require-dev and is not intended for cloud deployment.
  • The wildlive_test database must be created manually the first time (docker compose exec postgres psql -U wildlive -d wildlive -c "CREATE DATABASE wildlive_test OWNER wildlive;"). No test-DB bootstrap script is provided yet.
  • Migrations are not run automatically by the app container's entrypoint. Whether and how to run them at deploy time will be decided in a future deployment task.
  • No load, security, or resilience testing has been performed. This is a development foundation, not a production readiness certificate.

What was NOT done

All of the following were explicitly out of scope for Task 001 and remain unimplemented:

  • Any game domain — no User (WildLive-specific), Zoo, Hunter, Explorer, Region, Species, Animal, Exploration, Discovery, Expedition, or WorldEvent.
  • No authentication or authorization.
  • No frontend framework and no browser UI beyond Laravel's default welcome page.
  • No payment, billing, or purchase flows.
  • No X/Twitter integration or social posting.
  • No cloud deployment. Sakura Cloud AppRun and Sakura Cloud PostgreSQL appliance are named in the roadmap but nothing has been provisioned.
  • No public metrics, no player counts — WildLive has no players.
