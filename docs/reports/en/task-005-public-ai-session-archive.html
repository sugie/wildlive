Task 005 — Public AI Development Archive

Project: WildLive  ·  Date: 2026-08-14  ·  AI Agent: Claude Code (claude-opus-4-7[1m])  ·  Status: Merged into main

Human intervention

The human (repository owner) decided that WildLive should publicly archive the prompts and visible AI interactions used to build the project as an educational reference for AI-assisted software development. The human also set the language policy: development frequently happens in Japanese, but the public archive is published in English only as a faithful translation, while the bilingual (Japanese + English) HTML development reports under docs/reports/ are unchanged. The AI (Claude Code) designed and implemented the archive structure, the validator, the governance updates, and bootstrapped the archive with Task 005 (this task) as its first record.

Session note

The first two attempts to send the full specification arrived truncated in the chat channel. The AI declined to start any repository work on those turns and asked for a complete resend rather than filling in the missing sections by guessing. The full specification arrived on the third attempt. That entire visible history is preserved in docs/ai-sessions/task-005-public-ai-session-archive/transcript.en.md because it is part of how this task actually unfolded.

Objective

Turn WildLive into a public reference for AI-assisted software development: anyone reading the repository should be able to see what the human prompted, what the AI visibly replied, what commands ran, and which Pull Request and merge came out of the session — for every milestone the AI works on going forward.

This is governance and infrastructure only. No database migration, no Eloquent model, no game logic, no game API in this task.

Language and transparency policy (from this task)

  • Archive is English only. Prompts and transcripts are faithful English translations of the Japanese originals. Bilingual HTML reports under docs/reports/ continue to be produced in both languages.
  • Translation faithfulness. No summary, no beautification, no added or removed requirements, no meaning changes. Code, commands, paths, URLs, identifiers, and error messages stay in original form.
  • Visible only. No private chain-of-thought, no hidden reasoning. What is archived is what the human could see in the chat, plus verified tool activity.
  • No fabrication. Missing turns are marked Not captured or Not available in the public session record.
  • Security. No credential, token, cookie, .env value, or GitHub Secret value may appear in the archive. Real values are redacted as [REDACTED]. The validator's secret scanner enforces this.

Problems / Known Limitations

  • Session capture is human-driven. The MVP validator sanitises and publishes; it does not yet automate capture. A future task can wire up structured session logging once Claude Code exposes a stable JSON transcript surface. This task did not build a framework around undocumented Claude Code behaviour.
  • Post-merge metadata fields are optional. merge_commit, ci_status, and post_merge_ci_status may remain null in the shipped metadata.json; they can always be verified through the linked PR page and, if desired, backfilled in a small follow-up PR.
  • Prior milestones are not retroactively archived. Task 001 through Task 004 do not have session records; they can still be reconstructed from Git history, the PRs, and the bilingual HTML reports.
